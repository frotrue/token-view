# Token View 0.3.0-beta.1 배포 준비

이 버전은 Windows 수집기와 설치 가능한 모바일 웹앱(PWA)을 하나의 React 코드로 제공해요. 동기화는 각 사용자의 **구글 드라이브 앱 전용 공간**을 써요. 실제 Google Cloud 프로젝트 연결과 iPhone/Android 실기기 확인은 베타 배포 전에 직접 해야 해요. 빌드가 성공했다고 실제 계정 연결까지 검증된 것은 아니에요.

## 구현된 범위

- **PC**
  - 기존 SQLite 수집과 화면은 그대로예요.
  - 구글 계정 연결(브라우저 + PKCE)을 지원하고, 로그인 정보는 Windows 자격 증명 저장소에 저장해요.
  - 업로드: 내용이 바뀌었을 때만 최대 5분마다 gzip으로 올리고, 변화가 없으면 확인 시각만 갱신해요.
  - 예산·표시 설정을 공유하고, 휴대폰의 수집 요청을 처리해요.
- **모바일**
  - 구글 연결, PC 선택, 화면을 보고 있을 때 3분마다 조회, 1시간 토큰 만료 시 한 번 눌러 다시 연결.
  - JSON 가져오기와 다운로드, 명시적인 샘플 모드, 계정별 오프라인 캐시, 연결 해제 시 캐시 삭제, 홈 화면 설치.
- **화면:** 같은 기록의 사용량·비용·한도·예측·모델/프로젝트/세션/블록 통계를 보여 줘요. 오래된 기록은 수집 시점 기준으로, PC의 집계 시간대를 써서 계산해요.

**포함하지 않은 것**
- 모바일에서 제공자 계정에 직접 로그인해 한도를 가져오는 기능([검증 근거](provider-auth-feasibility.md)).
- 단가 재계산, PC 자동 실행·상태줄·Windows 알림 변경.
- 백그라운드 조회와 모바일 푸시 알림.

PC가 꺼져 있으면 새 기록과 한도는 수집되지 않아요.

## 로컬 실행

Node.js 24와 npm을 사용해요.

```sh
npm ci
npm run dev
```

브라우저에서 `http://localhost:1420`을 열면 돼요.
- **계정 없이:** 샘플 또는 JSON 가져오기를 쓸 수 있어요.
- **구글 연결까지 확인하려면:** `.env.local`에 웹 클라이언트 ID를 넣고, 구글 콘솔에 `http://localhost:1420`을 원본과 리디렉션 URI로 등록해요.

데스크톱 개발에는 Rust stable과 [Tauri 시스템 의존성](https://v2.tauri.app/start/prerequisites/)이 추가로 필요해요. 빌드에 넣지 않았다면 클라이언트 ID와 보안 비밀번호는 앱 설정의 고급 칸에 입력하면 돼요.

```sh
npm run tauri dev
```

## 모바일 배포 파일

1. [구글 드라이브 설정](cloud-setup.md)을 완료해요.
2. 빌드 환경에 `VITE_GOOGLE_CLIENT_ID`를 넣어요. 넣지 않으면 방문자가 앱에서 직접 입력할 수 있어요.
3. 다음 명령으로 검증하고 빌드해요.

```sh
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 시스템 Chromium이 있으면 그걸 써요. Windows에서는 `PLAYWRIGHT_CHROMIUM_PATH`에 Chrome 또는 Edge 실행 파일 경로를 지정하면 돼요.

**배포 방법**
- `dist/` 전체를 HTTPS 정적 호스트의 루트 경로(`/`)에 올려요. Cloudflare Pages/Netlify 형식의 `_headers`와 `_redirects`가 들어 있어요.
- `index.html`과 `sw.js`는 오래 캐시하지 않고, 해시가 붙은 `assets/` 파일만 오래 캐시해요.

**오프라인 캐시 규칙**
- 서비스 워커는 앱 코드와 아이콘만 캐시해요. 구글 응답은 캐시하지 않고, 개인 스냅샷은 별도의 IndexedDB에 저장해요.

## Windows 베타 설치 프로그램

`Beta checks` 워크플로의 `windows` 작업이 테스트 후 NSIS 설치 프로그램을 아티팩트로 만들어요. 저장소 변수에 구글 클라이언트 값이 있으면 그 값도 빌드에 넣어요. 서명 키 없이 만들고 GitHub Release는 게시하지 않아요.

```sh
npm ci
npx tauri build --bundles nsis --config '{"bundle":{"createUpdaterArtifacts":false}}'
```

서명된 공식 업데이트를 게시하려면 기존 Release 워크플로의 서명 키를 준비하고 `v0.3.0-beta.1` 같은 베타 태그를 써요. 하이픈이 있는 태그는 사전 릴리스로 올라가요. 그래서 정식 버전을 쓰는 사용자에게는 업데이트로 표시되지 않아요.

## 실제 연결 확인

[구글 드라이브 설정](cloud-setup.md#6-동작-확인)의 6단계를 따르고, 다음도 확인해요.

1. PC를 종료한 상태에서 마지막 기록이 유지되고 오래된 시각이 표시되는지
2. 휴대폰을 오프라인으로 바꾼 뒤 다시 열었을 때 저장된 기록이 보이는지
3. 다른 구글 계정으로 연결하면 이전 계정의 기록이 보이지 않는지, 연결 해제 후 오프라인으로 다시 열어도 개인 기록이 없는지
4. 드라이브 웹의 "앱 관리"에서 숨겨진 앱 데이터를 지운 뒤 PC가 다음 동기화 때 다시 만드는지

베타는 한 번에 PC 한 대의 스냅샷을 표시하고, 여러 PC를 합산하지 않아요. 스냅샷에는 최근 약 34일의 상세 시계열과 최근 500개 세션이 들어가요. 원본 SQLite 전체를 백업하는 형식은 아니에요.
