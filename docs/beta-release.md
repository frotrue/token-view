# Token View 0.3.0-beta.1 배포 준비

이 버전은 Windows 수집기와 설치 가능한 모바일 웹앱(PWA)을 하나의 React 코드로 제공합니다. 호스팅된 Supabase·실제 Windows 자격 증명 저장소·iPhone/Android 실기기의 최종 연결 확인은 베타 배포 전에 수행해야 합니다. 코드를 빌드했다고 실제 계정 연결까지 검증된 것은 아닙니다.

## 구현된 범위

- PC: 기존 SQLite 수집과 화면 유지, 선택적 클라우드 로그인/자동 업로드/재시도, Windows 자격 증명 저장, 공유 예산·표시 설정, 모바일의 새 수집 요청 처리.
- 모바일: 로그인, 기기 선택, 3분 조회와 화면 복귀 시 갱신, JSON 가져오기와 다운로드, 명시적인 샘플 모드, 계정별 오프라인 데이터, 로그아웃 시 캐시 삭제, 홈 화면 설치.
- 같은 기록의 사용량·비용·한도·예측·모델/프로젝트/세션/블록 통계. 오래된 기록은 수집 시점으로 계산하며 PC의 집계 시간대를 사용합니다.
- Supabase: 소유자별 읽기 정책, 검증된 RPC 쓰기, 오래된 덮어쓰기 차단, 요청 병합과 만료. 원본 로그·제공자 토큰을 저장하지 않습니다.

모바일에서 제공자 계정에 직접 로그인해 최신 한도를 가져오는 경로는 확인되지 않아 포함하지 않았습니다. [검증 근거](provider-auth-feasibility.md)를 참고하세요. PC가 꺼져 있으면 새 사용 기록·한도는 수집되지 않습니다. 모바일에서 단가 재계산, PC 자동 실행·상태줄 설정·Windows 알림을 변경하지 않습니다. 백그라운드 3분 실행과 모바일 푸시 알림도 포함하지 않습니다.

## 로컬 실행

Node.js 24와 npm을 사용합니다.

```sh
npm ci
npm run dev
```

브라우저에서 Vite가 표시하는 주소(기본 `http://localhost:1420`)를 엽니다. 계정 없이 샘플 또는 JSON 가져오기를 사용할 수 있습니다. 데스크톱 개발에는 Rust stable과 [Tauri 시스템 의존성](https://v2.tauri.app/start/prerequisites/)이 추가로 필요합니다.

```sh
npm run tauri dev
```

## 모바일 배포 파일

1. [Supabase 설정](cloud-setup.md)을 완료합니다.
2. `.env.example`을 참고해 `.env.local` 또는 빌드 환경에 공개 URL·키를 넣습니다. 설정 없이 빌드한 경우 방문자가 앱에서 직접 연결할 수 있습니다.
3. 다음 명령으로 검증·빌드합니다.

```sh
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 시스템 Chromium이 있으면 사용합니다. 다른 환경에서는 `npx playwright install chromium`을 먼저 실행하거나 `PLAYWRIGHT_CHROMIUM_PATH`로 실행 파일 경로를 지정합니다.

`dist/` 전체를 HTTPS 정적 호스트의 루트 경로(`/`)에 배포합니다. Cloudflare Pages/Netlify 형식의 `_headers`와 `_redirects`가 들어 있습니다. 다른 호스트는 이 파일의 보안 헤더와 SPA fallback을 동등하게 적용합니다. `index.html`, `sw.js`는 장기 캐시하지 않고 해시가 붙은 `assets/` 파일만 장기 캐시합니다. 하위 경로 배포는 이 베타의 기본 구성에 포함하지 않습니다.

Service Worker는 앱 코드와 아이콘만 캐시합니다. 로그인 응답이나 클라우드 API 응답을 HTTP 캐시에 넣지 않습니다. 개인 스냅샷은 별도의 IndexedDB에 저장합니다. 새 앱 버전은 기존 창을 닫고 다시 열 때 적용됩니다. 첫 온라인 방문과 다운로드 전에는 오프라인으로 실행할 수 없습니다.

## Windows 베타 설치 프로그램

`Beta checks` 워크플로의 `windows` 작업이 테스트 후 NSIS 설치 프로그램을 아티팩트로 생성합니다. 서명 키 없이 검증용 설치 프로그램을 만들며 GitHub Release를 게시하지 않습니다. 로컬 Windows에서는 다음과 같이 빌드할 수 있습니다.

```sh
npm ci
npx tauri build --bundles nsis --config '{"bundle":{"createUpdaterArtifacts":false}}'
```

서명된 공식 업데이트를 게시하려면 기존 Release 워크플로의 서명 키를 준비하고 베타 태그를 사용합니다. 이 브랜치의 작업으로 태그를 만들거나 Release를 게시하지 않습니다.

## 실제 연결 확인

로컬 검증에서는 TypeScript/Vite 프로덕션 빌드, 프런트엔드 단위 테스트 10개, 네이티브 테스트 14개, 실제 PostgreSQL 보안·동시성 검증 98개가 통과했습니다. 네이티브 코드는 Linux 전체 대상과 Windows GNU 전체 대상 컴파일을 확인했습니다. 브라우저 검증 범위와 결과는 [베타 테스트 기록](beta-test-results.md)에 정리했습니다. Windows MSVC 설치 프로그램 빌드는 GitHub Actions에서 별도로 확인합니다.

1. PC에서 로그인·동기화를 켜고 업로드 시각이 바뀌는지 확인합니다.
2. 휴대폰에서 같은 계정으로 로그인해 PC 기록과 비용이 일치하는지 확인합니다.
3. 휴대폰의 PC 한도 조회 요청 후 새 캡처와 실제 한도 확인 시각을 확인합니다. 제공자 조회 실패는 마지막 확인값과 구분해 표시되어야 합니다.
4. PC를 종료한 상태에서 마지막 기록이 유지되고 오래된 시각이 표시되는지 확인합니다.
5. 휴대폰을 오프라인으로 바꾸고 다시 열어 저장된 기록을 확인합니다. 다시 온라인으로 바꾸면 새 기록이 반영되어야 합니다.
6. 다른 계정과 다른 기기를 선택한 뒤 이전 계정의 기록이 표시되지 않는지 확인합니다. 로그아웃 후 오프라인 재실행에서도 개인 기록이 없어야 합니다.
7. Windows 앱 재시작 후 로그인 복원, 세션 갱신, 로그아웃 후 복원 차단을 확인합니다.

베타는 한 번에 PC 한 대의 스냅샷을 표시합니다. 여러 PC 합산과 원본 DB 복원은 제공하지 않습니다. 클라우드 스냅샷은 4 MiB 제한이며 현재 화면의 35일 상세 시계열·최근 500세션을 포함합니다. 원본 SQLite의 모든 이벤트를 백업하는 형식은 아닙니다. 파일 가져오기는 최대 8 MiB까지 지원합니다.
